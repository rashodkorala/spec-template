# Device tests

Physical test cases: checks that only a real device can prove.
Each case is one file with everything needed to run it without asking anyone: what you need, how to set up, numbered steps with what you should see after each, pass and fail rules, how to clean up, and a results log.

Automated tests live in the code repos.
A rule that only those tests cover stays **BLOCKED** in the feature's `validation.md` until its device case here passes on that platform.

## How it is organised

- **One folder per feature**, named as in `features/`: `device-tests/<feature>/DT-<AREA>-<nn>-<slug>.md`.
- **One case per behaviour, for every platform it applies to.** Steps are written once; only real differences are split ("**Android:** … **iOS:** …"), with platform-only setup under "Platform notes".
- **Each case has a platform table** with a status per platform (platforms are listed in `scripts/spec_config.py`). The result is not typed there: it is the newest row for that platform in the case's **Results** log.
- **The index below is generated** from the cases by `scripts/device-tests`; `scripts/check` fails when it is stale.

## How to run a case

1. Do the [shared setup](#shared-setup) for your phone once per session.
2. Open the case, check its platform table (the build to test) and **Before you start**, then follow the steps.
3. After each step, compare what you see with **Expect**. At the first mismatch, stop: that is a fail.
4. Add a row to the case's **Results**: date, platform, who, phone and OS, app build, `PASS` or `FAIL`, notes. For a fail, note the step number and what you saw; a screenshot helps.
5. Run `scripts/device-tests` to refresh the index, then tell the agent. It records the evidence in the feature's `validation.md` and the bug or change file, and closes or reopens it.

## Shared setup

### Android

- Phone: USB debugging on (Settings › Developer options), plugged in, "Allow USB debugging" accepted.
- Check the phone is connected: `adb devices` lists it as `device`.
- To kill the app for a cold-start test, use `adb shell am kill <package>` (or `run-as <package> kill -9` on a debug build). Force stop also cancels scheduled work, so only use it when the case says so.

### iOS

- iPhone: plugged into the Mac and trusted; the build to test installed from Xcode or TestFlight as the case says.
- **Watch the app's log:** Console.app › select the iPhone › Start streaming, then filter by the app's subsystem.
